# ai-commerce-edit
我的电商skill

根据脚本和已有AI视频、实拍、商品图片或手剪草稿，制作电商产品短片，交付可继续编辑的工程。当前技能版本：**0.2.0**。

## 能做什么

- 每条重新核对对应脚本、实际素材与最新草稿，按内容分析剪法。
- 保留用户有效的段落安排、最新字幕、声音、变速及局部设计。
- 完整第一版纳入必要的字幕动效、转场、逐镜颜色和声音处理，再按看片反馈精修。
- 区分普通字幕、短卖点强调和独立信息字卡，按画面与信息需要决定手法。
- 优先文件方式工作，非必要不控制电脑；分开说明文件、静帧、连续播放与编辑器重载的验证结果。

纯口播去停顿、参考广告复刻生成、视频生成提示词及单独导出有各自的工作流程，不以本技能为主。

## 安装与调用

可在Codex中让 `$skill-installer` 从此仓库安装根目录的技能：

```text
使用 $skill-installer，从 https://github.com/santoro-1/ai-commerce-edit
安装仓库根目录的技能，名称为 ai-commerce-edit。
```

也可以下载仓库，将 `SKILL.md`、`agents/` 和 `references/` 一起放入当前Codex支持的技能目录下的 `ai-commerce-edit/` 文件夹。官方文档列出的用户级目录为 `~/.agents/skills/`；已有环境若使用其他受支持目录，以实际发现结果为准，不要重复安装同名技能。

在新聊天明确调用 `$ai-commerce-edit`。Codex可检测技能变化；若列表未刷新，可重启后再检查。参见[官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

## 开剪前提供什么

1. **脚本**：文件或可访问路径，表格中的具体标题；容易重名时加工作表或对应台词。
2. **最新草稿**：项目名及位置，说明已保存；已有手剪安排也请保留。
3. **素材**：所在位置，或说明已全部放入草稿；新增镜头停在末尾时说明它们的用途。
4. **当前产品口径**：卖点、参数、活动及禁用说法；脚本与补充信息冲突时指定以哪个为准。
5. **本轮范围**：先方案还是按已确认方案执行，哪些区域暂不改，字幕参考哪份、是否自行添加BGM。

### 新聊天示例

```text
使用 $ai-commerce-edit，剪辑《脚本标题》。
脚本：<文件路径及对应标题>
最新剪映草稿：<项目名和路径，已保存>
素材：<素材目录，或已全部放入草稿>
产品和活动：<当前确认信息，或见脚本>
字幕沿用当前草稿最新样式，保留完整台词。
先读脚本和最新稿，给针对性方案，等我确认再改。
非必要不控制电脑，BGM我自己加。
```

规则和案例保存在技能文件中；历史聊天里的全部细节、草稿位置及新素材状态不会随调用名自动转移。只说“按上一条来”不足以确认新项目的具体参数。

## 运行条件与验证边界

**只下载本技能，还不能保证直接修改剪映草稿。** 技能提供工作方法，实际执行还需要能访问本地文件并运行命令的Agent环境、剪映和兼容的草稿读写工具。配齐并验证这些条件后，可采用本次的文件处理方式修改草稿。

| 工具或条件 | 作用与配置 |
|---|---|
| 本地Agent执行环境 | 可以读写用户授权的草稿/素材目录并运行本机命令；纯网页聊天不能仅凭本地路径访问电脑 |
| 剪映及完整项目素材 | 提供真实工程、字体和已下载的动画/转场资源；目标稿先保存，确定实际使用的时间线 |
| Windows x64＋匹配的剪映运行时 | 这是本次 `jy-draftc` Windows执行链的前提；其他平台需独立适配验证 |
| [jy-draftc原项目](https://github.com/wenshui330/jy-draftc) | 加密草稿的解密与回加密；从[Releases](https://github.com/wenshui330/jy-draftc/releases)选择与剪映运行时匹配的包，配置 `JY_INSTALL_DIR` 指向含 `videoeditor.dll` 的版本目录 |
| Python 3.11、[FFmpeg/ffprobe](https://ffmpeg.org/download.html) | 本次用于工程处理、探测、抽帧、音频和派生媒体；FFmpeg的可执行文件需可定位 |
| [pyJianYingDraft](https://github.com/GuanYixuan/pyJianYingDraft)及按需Python库 | 本次使用0.3.0构建部分素材/效果；不是加解密工具。图片、音频计算和表格读取分别按需使用Pillow、NumPy、openpyxl |

配置步骤、可复制的检查命令、旧版与新版加解密接口区别，以及首次副本验证流程，见 **[本地工具与剪映草稿读写配置](references/local-tools.md)**。

仓库不捆绑可执行工具、剪映DLL、字体、付费效果、项目素材或本次逐片执行脚本。Agent仍需依据当前工程结构编写或适配修改流程；它不是装好就有全部按钮的一键剪辑插件。明文草稿可以跳过加解密，已有可靠工具可沿用，不强制更换剪映版本或安装整套依赖。

0.2.0已做技能结构、引用和修改范围检查，并进行十项场景推演；尚未完成升级后新视频的实际剪辑与用户审片验证。文件校验不能代替原生连续带声播放。
